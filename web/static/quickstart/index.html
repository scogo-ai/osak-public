API and MCP quickstart

Start with a browser test, then use the same API key in Claude Code or the local Codex app.

1. Test the API in Swagger

Open Swagger UI. For each route, click Try it out, enter the inputs shown below, then click Execute.

  1. Check the service. Run GET /api/v1/health. HTTP 200 confirms reachability. The response also reports dataset health and freshness.
  2. Check the feeds. Run GET /api/v1/sources. For Cisco and Fortinet, look for cisco_openvuln and fortinet_psirt_rss. Check their last successful sync times.
  3. Verify your key. Request a key if you need one. In Swagger, click Authorize, paste the key into BearerAuth, and authorize. Swagger adds the Bearer prefix. Run GET /api/v1/me and expect 200 with your account details.
  4. Browse advisories. Run GET /api/v1/advisories with vendor set to fortinet or cisco and page set to 1. The response lists advisory IDs for that vendor.
  5. Inspect one advisory. Run GET /api/v1/advisories/{id} with FG-IR-26-268 for FortiGuard or cisco-sa-9800cl-openscep-SB4xtxzP for Cisco. Look for ranges, urls, and provenance.
  6. Resolve a raw device string. If that is how your inventory arrives, run POST /api/v1/resolve with {"raw_strings":["Fortinet FortiOS 7.2.4"]}. Expect resolved and product ID fortinet-fortios.
  7. Match a device. Run POST /api/v1/match with the sample body below.
{
  "assets": [
    {
      "asset_ref": "lab-fortigate",
      "vendor": "fortinet",
      "os": "FortiOS",
      "version": "7.2.4",
      "features": ["rest_api"]
    }
  ]
}

In the response, find lab-fortigate and the finding for CVE-2023-33301. This sample should show affected with a source link once the relevant advisory feed is ready. An unknown verdict means the available evidence is incomplete. Use source status to check sync. If /me returns 401, authorize again with your current key.

Integration endpoint POST https://osak.lab.scogo.ai/api/v1/match. See the OpenAPI schema for the full contract.

2. Set the MCP key on your Mac

Run this in Terminal and paste the same OSAK key when prompted. The key stays out of the MCP configuration and your test prompts.

printf 'OSAK API key: '
read -rs OSAK_API_KEY
printf '\n'
export OSAK_API_KEY

Claude Code

In your test project, add the following to .mcp.json. If the file already exists, add the osak entry to its mcpServers object.

{
  "mcpServers": {
    "osak": {
      "type": "http",
      "url": "https://osak.lab.scogo.ai/mcp",
      "headers": {
        "Authorization": "Bearer ${OSAK_API_KEY}"
      }
    }
  }
}

From the same terminal and project folder, run claude. Approve the project’s OSAK server if prompted. Run /mcp and check that osak is connected. Claude Code MCP docs.

For the Claude desktop app on macOS, run launchctl setenv OSAK_API_KEY "$OSAK_API_KEY" in that terminal. Quit and reopen Claude, then open the Code tab and start a local session for the same project folder. Claude desktop configuration.

Codex desktop app

With the Codex CLI installed, run these commands from the same terminal. The desktop app and CLI share MCP configuration on this Mac.

codex mcp add osak --url https://osak.lab.scogo.ai/mcp \
  --bearer-token-env-var OSAK_API_KEY
launchctl setenv OSAK_API_KEY "$OSAK_API_KEY"

Quit and reopen the Codex app, then start a Local session. Type /mcp to check that osak is connected. Codex MCP docs.

3. Try these prompts in either client

  1. Use the OSAK get_advisory tool for CVE-2023-33301. Give me the advisory ID and one source link.
  2. Use the OSAK check_assets tool to compare Fortinet FortiOS 7.2.4 and 7.2.5. Include the rest_api feature on both. For CVE-2023-33301, report each verdict, the reason, and a source link.

Open the tool call in your session to confirm it used osak. The first prompt should return the requested advisory. With the relevant feed ready, the second should report affected for 7.2.4 and not_affected for 7.2.5 for this advisory.
